# UI Demo（纯前端、单仓 mock）

直接双击 `index.html` 即可打开；无构建、无服务器、无网络请求。

> **能力边界**：这个 Demo 不是真实 dsh-sast 实现。它只展示一个仓库的目标 UI；不读取用户的
> `SKILL.md`、不分析代码、不创建 repository worker，也没有 100 仓队列、重试、恢复或批次报告。

| 内容 | Demo 中的来源 | 目标实现 |
| --- | --- | --- |
| 用户审计方法论 | `mock-data.js` 手写 builtin/workspace/user 数组 | 用户/团队方法论经受信 `ctx.skills` 发现并按 digest 固定 |
| intent / fact / finding / asset | 全部手写 | 根据每仓方法论、recon 和新证据动态产生 |
| 58 步推进与文件触达 | `MOCK.script/coverageAt` 手写 | 成功工具事件 + 耐久 store 动态折叠 |
| check 状态、纳入率、完成度、阶段 | 前端依据 mock intent 动态推导 | store/投影依据真实事件推导 |
| “添加方法论 / 生成意图” | 仅修改浏览器内存的 UX 模拟 | 对话工具注册用户方法论并创建真实 intent |
| 多仓批次 | **没有** | 1～100 仓由 DurableBatchScheduler 默认逐仓串行 |

因此，这里看到的任务与进度是“对固定假数据的动态呈现”，不是 agent 正在扫描。目标架构的任务不是
写死模板：固定的是权限角色和阶段分类，实际 intent 的数量、范围、状态与产出按仓动态变化。

- `index.html` — 结构与控制条
- `styles.css` — 样式
- `mock-data.js` — 单仓手写假数据
- `app.js` — 本地重放、派生指标与交互

多仓与阻塞策略见 [architecture.md](../architecture.md) §2（批次控制面四表）与 §6（spike-D 硬闸门）。

## 这个 demo 想让你确认什么

| # | 看哪里 | 确认什么 |

| 8 | **报告** | Markdown 预览 + 复制/下载/SARIF；确认“用户审计方法论与检查项覆盖”、顺带发现及技术标识 `ruleId=<skillId>/<checkId>` |
| 9 | **漏洞** 页顶部「演示：路径硬校验」→ 看一眼 | 模型引用了不存在的文件时，被拒绝的调用长什么样、错误文案是否可行动（ADR-03） |

## 用户审计方法论面板建议按这条路径确认

1. 进入主审计会话 → **任务与进度**，确认三种来源徽标和各 check 状态。
2. 对 `todo` 点“模拟生成审计意图”：状态转为 `planned`，卡片与纳入数同步增加。
3. “模拟生成全部”只补 todo；停用方法论退出活动分母，重新启用恢复清单。
4. “模拟添加用户方法论”只写浏览器内存；重置后方法论、启停与临时 intent 都恢复初始 mock。

真实产品的用户/团队方法论写在受信 `SKILL.md` 中，DSH `ctx.skills` 只是发现载体；agent 调用
`sast_register_skill` 固定检查承诺，批次再固定正文 digest/artifact。当前浏览器保持只读，按钮只确认 UX。

## 会话切换：五行覆盖四条命中路径

点击左侧任意会话即可切换。这是 `src/client/index.ts` 里 `isSastSession` 判定逻辑的可视化。

| 会话 | 预设 | `sastMounted` | 标签 | 命中依据 |
| --- | --- | --- | --- | --- |
| `s-3ab1` 主审计会话 | `sast` | true | ✓ | 预设名命中；有完整投影 |
| `s-7f3a` 委派子会话 | `sast`（继承父预设） | true | ✓ | 预设名 + 自身有 `sast_submit` 记录 |
| `s-91c2` 派生预设 | `audit-lab` | true | ✓ | **只靠 `sastMounted`**（预设改了名，判定不认识它） |
| `s-2b7d` 子会话 | `audit-lab` | false | ✓ | **只靠祖先链**（自身零证据，上溯到 `s-91c2` 命中） |
| `s-5d40` 普通会话 | `standard` | false | ✕ | 三条都不命中 → 标签整个消失 |

主审计会话首次进入默认打开「白盒审计」；其余会话首次进入默认打开**自己的对话**。主视图选择按会话保存，
不会继承刚离开的会话，因此以下两条路径结果一致：

- `s-3ab1 → s-7f3a / s-91c2 / s-2b7d`：显示目标会话自己的 user/assistant/tool 内容；
- `s-5d40 → s-7f3a / s-91c2 / s-2b7d`：同样显示目标会话自己的对话，不因来源会话不同而变。

2/3/4 会话的「白盒审计」标签仍然可见，用来演示预设名、`sastMounted` 和祖先链三种命中方式；用户
**主动点击**该标签时才显示 null 投影空态。这些会话自己没有调用 `sast_start_scan`，子会话只通过
`sast_submit` 写入父会话，所以不会复制父图。进入空态时 Demo 会清空上一会话的 header/sub-tabs/content，
并强制 `[hidden]` 不受 flex 样式覆盖，因此空态下方不会再出现第一个会话的旧内容。

审计图仍只有一份，挂在发起扫描的主会话上；这里不把父图伪装成子会话自己的投影。

切到非主审计会话时，播放条的重放控件会灰掉（重放只对主会话有意义），语言切换仍可用。

## 与真实实现的差异（demo 的取巧之处）

- 图是手写的 SVG + 绝对定位 HTML 节点，真实实现用 `@xyflow/react`；但**分层布局算法照搬了 `graph.ts` 的
  `depthsOf`(BFS) + `stackByDepth`**，所以图形排布与最终效果一致。布局链路使用 `body/shell/sast-body`
  纵向 flex + `min-height:0`，`.graph-wrap` 另有 `min-height:320px`，防止绝对定位节点把父容器撑高失败。
- Demo 的方法论表单直接改内存状态；真实 v1 不从浏览器写 store，而是由 DSH Skill registry 发现方法论，
  `sast_register_skill` 保存经校验的会话快照。被审计克隆不会自动成为受信方法论来源。
- Markdown 预览用的就是设计里那套「受限子集渲染」：只认 `#`/`##`/`###`/`-`/`  N.`，全程 `textContent`，
  数据从不进 `innerHTML`。
- 文件覆盖数据是脚本里的 mock 快照；检查项纳入率与状态会根据启用方法论和临时 intent 在前端实时计算。
  真实实现两者都由完整方法论会话快照 + 存储层记录计算。
- 没有后端：所有"工具调用"都是本地的假数据推进。
